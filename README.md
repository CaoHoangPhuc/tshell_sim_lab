# Tessent Shell Simulation Lab

An educational Python lab for exploring a small subset of Tessent-style DFT workflows, scan insertion, and stuck-at fault simulation. It is an independent project and is not affiliated with Siemens. The simulator is a teaching model: DRC, patterns, and coverage have not been validated for design assessment or sign-off.

The lab includes a command-line shell, a restricted JSON-to-Verilog scan insertion tool, a small standalone fault simulation example, and case-study references. The implementation is not full Tcl, Tessent, ATPG, TSDB, or STIL.

## Installation

Use Python 3.9 or newer:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
```

The core tools use the Python standard library. PyMuPDF is optional and is only needed to read a separately supplied PDF. Icarus Verilog (`iverilog` and `vvp`) is optional for RTL tests; install it with `brew install icarus-verilog` on macOS.

## Usage

```sh
tshell --demo
tshell-insertion --spec examples/serial_adder.json -o output/serial_adder_scan.v
tshell-scan-sim --case all
```

Start the interactive shell with `tshell`. The generated Verilog from `tshell-insertion` contains an educational generic scan chain; it is not technology mapped. In the shell, command support and simulation are intentionally limited. Rules that cannot be checked reliably must not be treated as passing, and reported coverage is illustrative only.

Commands can also be run with `tshell -c '...'` or `tshell -f script.do`. Relative design paths are resolved from the current working directory. See [the roadmap](docs/plans/2026-11-14-tshell-roadmap.md) for limitations and planned validation.

## Supported Verilog subset

The shell accepts a single module with non-ANSI scalar `input`, `output`, `wire`, and `reg` declarations. Continuous assignments support scalar identifiers, one-bit binary literals, parentheses, and bitwise `~`, `&`, `^`, and `|` expressions. Built-in `and`, `or`, `xor`, `nand`, `nor`, `not`, and `buf` primitive instances use positional scalar pins.

Sequential support is limited to the `always @(posedge clk)` form generated by `tshell-insertion`, where `clk` is a primary input: an active-high synchronous reset to zero, followed by a scan-enable branch and a capture branch assigning the same registers. ANSI-style port declarations, buses, hierarchical modules, commercial cell instances, internal or gated clocks, asynchronous resets, and other behavioral constructs are unsupported and rejected. Clock and fault simulation remain educational and are not validated for sign-off.

## Tests

```sh
python -m pytest -v
# or
python -m unittest discover tests -v
```

RTL-dependent tests are skipped if Icarus is unavailable. Tests that read user-supplied manual pages require PyMuPDF.

## Reference manual

The repository and package include a rule and case-study index with identifiers and page references; they do not include PDF files or full manual pages. Use your own authorized copy with the exercise commands as described in [EXERCISES.md](EXERCISES.md). The `run`, `source`, and `commands` exercise operations read the specified PDF locally; no manual text is written into the index. `python tools/build_knowledge_db.py` rebuilds the metadata-only index from `tessent_core/drc_catalog.json`.

## Project structure

- `tshell.py`: interactive shell and batch entry point.
- `insertion.py`: restricted JSON-to-Verilog scan insertion.
- `scan_sim.py`: standalone two-flop fault demonstration.
- `tessent_core/`: logic, netlist, session, DRC, fault simulation, and metadata index.
- `exercises.py` and `rtl/`: manual-based exercises and optional RTL simulations.
- `tests/`: automated tests.
